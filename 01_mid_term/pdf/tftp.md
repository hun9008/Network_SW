# TFTP (Trivial File Transfer Protocol) RFC 1350 정리

---

## 1. 개요
- **목적**: 간단한 파일 전송을 위한 경량 프로토콜.
- **운영 방식**: UDP(사용자 데이터그램 프로토콜) 위에서 동작.
- **기능**:
  - **읽기 요청 (RRQ)**: 서버에서 파일 읽기.
  - **쓰기 요청 (WRQ)**: 서버로 파일 쓰기.
- **전송 모드**:
  1. **netascii**: ASCII 텍스트 형식 (네트워크 표준).
  2. **octet**: 원본 바이너리 데이터 전송.
  3. **mail**: 데이터를 메일로 전송 (현재는 사용되지 않음).

---

## 2. 패킷 구조
### 2.1 RRQ/WRQ (읽기/쓰기 요청) 패킷

- **Opcode**: 1 (RRQ) 또는 2 (WRQ)  
- **Filename**: 요청할 파일명  
- **Mode**: `"netascii"` 또는 `"octet"`

### 2.2 DATA (데이터) 패킷

- **Opcode**: 3  
- **Block #**: 전송되는 데이터 블록 번호 (1부터 시작)  
- **Data**: 0~512 바이트 크기의 데이터

### 2.3 ACK (인증 응답) 패킷

- **Opcode**: 4  
- **Block #**: 응답하는 데이터 블록 번호  

### 2.4 ERROR (오류) 패킷

- **Opcode**: 5  
- **ErrorCode**: 오류 코드 (예: 파일 없음, 접근 거부)  
- **ErrMsg**: 오류 메시지 (네트워크 ASCII 형식)

---

## 3. 데이터 전송 흐름
1. **연결 과정**:
   - 클라이언트가 **RRQ** 또는 **WRQ** 패킷을 서버로 전송.
   - 서버가 **ACK** 또는 첫 번째 **DATA** 패킷으로 응답.
   - 각 데이터 패킷에 대한 ACK가 수신되면 다음 블록이 전송됨.

2. **데이터 전송**:
   - 데이터는 512바이트 고정 크기의 블록으로 전송.
   - 마지막 블록이 **512바이트 미만일 경우** 전송 종료 신호.

3. **타임아웃과 재전송**:
   - 패킷 손실 시 타임아웃 후 마지막 패킷을 재전송.

---

## 4. 오류 처리
- 오류 발생 시 **ERROR** 패킷이 전송됨.
- **주요 오류 코드**:
  - `1`: 파일 없음
  - `2`: 접근 거부
  - `3`: 디스크 용량 부족
  - `4`: 잘못된 TFTP 작업
  - `5`: 알 수 없는 전송 ID
  - `6`: 파일이 이미 존재함
  - `7`: 사용자 없음

---

## 5. 초기 연결 프로토콜
1. **쓰기 요청 (WRQ)**:
   - 클라이언트 → 서버: WRQ 전송 (대상 포트 69).
   - 서버 → 클라이언트: ACK(블록 번호 0) 응답.
   - 데이터 전송 시작.

2. **읽기 요청 (RRQ)**:
   - 클라이언트 → 서버: RRQ 전송.
   - 서버 → 클라이언트: 첫 번째 DATA(블록 번호 1) 응답.

---

## 6. 전송 종료
- **512바이트 미만**의 마지막 DATA 패킷이 전송되면 전송 종료.
- 서버는 ACK 유실 시 일정 시간 대기 후 ACK 재전송 가능.

---

## 7. 보안 고려 사항
- **인증 기능이 없음**: 파일 접근 권한을 엄격히 제한해야 함.
- 서버는 **공개 읽기 권한만** 있는 파일에 접근하도록 설정.
- **쓰기 작업 비활성화**를 권장.

---

## 8. 패킷 흐름 예시
### 쓰기 요청 (WRQ) 흐름
1. 클라이언트 → 서버: **WRQ** 전송 (대상 포트 69).
2. 서버 → 클라이언트: **ACK**(블록 번호 0) 응답.
3. 클라이언트 → 서버: **DATA**(블록 번호 1) 전송.
4. 서버 → 클라이언트: **ACK**(블록 번호 1) 응답.
5. 마지막 DATA 패킷이 512바이트 미만일 경우 전송 종료.

---

## 9. 결론
TFTP는 간단하고 가벼운 파일 전송 프로토콜입니다. UDP 기반으로 동작하므로 빠르지만 패킷 손실에 취약합니다. 타임아웃과 재전송 메커니즘으로 신뢰성을 보장하며, 보안을 위해 접근 권한을 엄격히 설정해야 합니다.
